# 三模型 A/B/C 对比方案

## 目标

对比 3 个模型的挖掘效果，核心是评测 doubao 精调模型。验证分两个维度：

1. **精调验证**：在 doubao 精调所覆盖的交通标志/地面箭头场景上，评估精调带来的提升
2. **泛化验证**：在精调未覆盖的场景上，评估底座模型的泛化能力

### doubao 精调覆盖范围

| 类别 | 数量 | 包含 |
|---|---|---|
| 地面箭头 | 12 | 掉头/左转/右转/直行/合流等各类箭头及组合 |
| 警告标志 | 11 | 施工、弯道、窄桥、注意儿童等 |
| 禁止标志 | 11 | 限速、禁转、禁行、禁超车等 |
| **合计** | **34** | |

### 验证逻辑

doubao 精调的是交通标志/地面箭头识别，我们的标签是驾驶行为场景。两者不直接重合，但交通标志是场景的**视觉线索**——识别了标志就能辅助判断场景。例如：之前模型对左右转识别能力弱，而精调模型能识别左右转地面箭头，应该能提升识别左右转相关标签的准确率。

## 维度一：精调验证（6 个交通标志/标线识别任务）

### 验证目的

doubao 精调数据覆盖 34 个标签，从三大类中各选 2 个有代表性的标签，验证精调带来的识别精度提升。

### 选取的 6 个标签

| 类别 | 标签 | 选取理由 |
|---|---|---|
| 地面箭头 | 掉头箭头 | 与路口通行强相关，且容易和左转箭头混淆 |
| 地面箭头 | 左转掉头组合箭头 | 组合标线，考验精细辨别能力 |
| 警告标志 | 道路施工标志 | 与施工区巡航场景直接关联 |
| 警告标志 | 注意儿童标志 | 学校区域场景，有安全价值 |
| 禁止标志 | 禁止掉头标志 | 与 U-turn 标签直接互补 |
| 禁止标志 | 区域限速标志 | 与限速巡航场景直接关联 |

### 数据池

与泛化验证共用同一个 5000 张图片池（`sample_images.txt`），保证数据一致。

### 6 个 Prompt

| 代号 | 场景 | Prompt 文件 | 输出 |
|---|---|---|---|
| `img_uturn_arrow` | 掉头箭头 | `scene_tag/prompt_txt/img_uturn_arrow.txt` | `true` / `false` |
| `img_left_uturn_arrow` | 左转掉头组合箭头 | `scene_tag/prompt_txt/img_left_uturn_arrow.txt` | `true` / `false` |
| `img_construction_sign` | 道路施工标志 | `scene_tag/prompt_txt/img_construction_sign.txt` | `true` / `false` |
| `img_children_sign` | 注意儿童标志 | `scene_tag/prompt_txt/img_children_sign.txt` | `true` / `false` |
| `img_no_uturn_sign` | 禁止掉头标志 | `scene_tag/prompt_txt/img_no_uturn_sign.txt` | `true` / `false` |
| `img_speed_limit_sign` | 区域限速标志 | `scene_tag/prompt_txt/img_speed_limit_sign.txt` | `true` / `false` |

### Token 估算（单任务 × 5000 张）

| 项目 | 值 |
|---|---|
| 每张总输入 token | ~600-900（prompt 较短） |
| 每张输出 token | ~50-100 |
| 5000 张总输入 | ~300-450 万 |
| 六个任务合计输入 | ~1,800-2,700 万 |

### 耗时估算

| 项目 | 值 |
|---|---|
| 单张推理 | ~2-5 秒（prompt 更短） |
| 单任务 5000 张（concurrency=4） | ~40-100 分钟 |
| 六个任务合计 | ~4-10 小时/模型 |

### 预期结论

| 结果 | 含义 |
|---|---|
| doubao >> qwen | 精调有效，在精调覆盖的场景上大幅提升 |
| doubao ≈ qwen | 精调对底座提升不明显，或 qwen 底座已足够强 |
| doubao < qwen | 精调可能引入了偏差，底座能力被削弱 |

### 任务 B：视频自车驾驶行为标注（2 组 Prompt）

#### 验证逻辑

doubao 精调的是交通标志/地面箭头，不直接覆盖驾驶行为标签。但交通标志是驾驶场景的视觉线索：
- 识别了**掉头箭头** → 有助于判断 `Intersection_StandardUTurn`
- 识别了**左转箭头** → 有助于判断 `Intersection_ProtectedLeftTurn`
- 识别了**施工标志** → 有助于判断 `LaneCruising_ConstructionZone`
- 识别了**限速标志** → 有助于判断 `LaneCruising_RoadSpeedLimit`

如果 doubao 在视频任务上也有提升，说明精调的标志识别能力可以**间接传递**到场景理解。

#### 数据池

| 项目 | 值 |
|---|---|
| 来源 | 从 154K 挖掘池（路口场景 20s segments）分层抽样的 10K 列表中随机抽取 |
| 列表 | `scene_tag/results_ab_compare/sample_1000.txt`（已生成，勿重新抽样） |
| 采样量 | 1000 条 20s 视频 |
| 抽帧 | 2FPS → 40 帧/条，分辨率 256×256 |

#### 两组 Prompt

| 代号 | 场景 | Prompt 文件 | 标签数 |

| `05_LaneCruising` | 车道巡航 | `scene_tag/prompt_txt/05_LaneCruising.txt` | 18 |

## 执行步骤

### Step 1：填入豆包 API

编辑 `scene_tag/launch_ab_compare.sh`：

```bash
DOUBAO_API_BASE="http://豆包API地址/v1"
DOUBAO_MODEL="豆包模型名"
```

### Step 2：启动对比

```bash
cd /root/workspace/LLaMA-Factory

# 跑全部三个模型（不可达的会自动跳过）
bash scene_tag/launch_ab_compare.sh all

# 或按维度跑
bash scene_tag/launch_ab_compare.sh doubao finetune   # 只跑 doubao 的精调验证
bash scene_tag/launch_ab_compare.sh doubao generalize  # 只跑 doubao 的泛化验证
bash scene_tag/launch_ab_compare.sh doubao image       # 只跑 doubao 的全部图片任务
bash scene_tag/launch_ab_compare.sh doubao video       # 只跑 doubao 的视频任务

# 或单独跑某个模型的全部任务
bash scene_tag/launch_ab_compare.sh doubao
bash scene_tag/launch_ab_compare.sh qwen35
bash scene_tag/launch_ab_compare.sh qwen235b
```

> qwen235b 需先部署：`python scene_tag/11_deploy.py --preset qwen3-vl-235b`（需 4×A100）

### Step 3：查看结果

```bash
python3 scene_tag/analyze_ab_compare.py
```

## 评测维度

| 维度 | 精调验证 | 泛化-图片 | 泛化-视频 |
|---|---|---|---|
| **Precision** | 人工抽查正例 | 已知正样本的召回率 | 每标签抽 20 条审核 |
| **命中数** | 各模型 positive 数对比 | 各模型 positive 数对比 | 各标签命中数 |
| **一致性** | 同图片判定一致率 | 同图片判定一致率 | 同视频标签一致率 |
| **推理速度** | 单张平均耗时 | 单张平均耗时 | 单条视频平均耗时 |

## 注意事项

1. 三个模型必须用相同的样本列表（`sample_1000.txt` + `sample_images.txt`），不要重新抽样
2. 235B 部署需要 4×A100（当前 GPU 0-2 被占，需等释放或用其他机器）
3. 所有脚本支持断点续传，中断后重新跑会跳过已处理的数据
4. 所有脚本用 nohup 后台运行，合盖不影响
5. 建议执行顺序：精调验证（轻量，最快出结论）→ 泛化-图片 → 泛化-视频（最耗时）
